# Workspace guide

The application lives in one checkout on `checkpoint/beta.27`. Older branch names and historical reports are not separate current applications. Do not use a blanket `git clean`, delete all of `out/`, or treat every ignored folder as disposable: protected recovery material also lives under ignored output.

| Location | Purpose / retention |
| --- | --- |
| `src/`, `native/`, `resources/` | Active application, tests, native sampler and approved assets. Keep. |
| `build/`, root configs and lockfile | Installer/build inputs. Keep; `build/` is source, not disposable output. |
| `scripts/` | Build, source-export, localization, scientific and packaged-workflow tools. Some are historical; lack of an import does not mean a standalone test is unused. |
| `docs/` | Current entry points and dated audit/design/research evidence. Preserve audit reproductions, regression/upgrade evidence and provenance records. |
| `node_modules/` | Locked installed toolchain. Recreate with `npm ci` when needed; keep for normal development. |
| `out/main`, `out/preload`, `out/renderer`, `out/native-foreground` | Current compiled output. `npm run build` regenerates it. |
| `out/qa-temp/` | Isolated fictional test output and generated comparison engines. Some folders have uncertain provenance; check before deleting. Never run tests against a personal profile. |
| `dist/development/` | Default future production packaging output. Reuse this location instead of accumulating date-stamped copies. It is not an approved release. |
| `dist/qa/` | Future inspector-enabled QA packaging from `npm run build:qa`. Explicit marked fictional data directory remains mandatory. Never distribute. Rebuild production after QA. |
| `dist/rc-beta28-rc2-20261018/` | Immutable verified RC2, matching source/dependencies, notices, checksums and unpacked runtime. Do not overwrite or clean. |
| `dist/rc-beta28-20261018/`, `dist/stage4-beta27/` | RC1 failure reproduction and older beta.27 upgrade/baseline targets. Retained intentionally. Never install RC1 over a real profile. |
| `dist/private-friend-rc2-20261018/` | Exact held testing ZIP, manifest/checksums and hold notice. Expanded duplicate can be regenerated by extraction into a fresh disposable directory. Asset-rights hold still applies. |
| `publication-local/` | Private source review/staging and older snapshots. Not published. Contains protected backup material: never remove wholesale. |
| `docs/verification/` | Dated reports, receipts, visual and statistical evidence. Existing tracked receipts stay tracked; new evidence is ignored until reviewed and explicitly added. |
| `docs/archive/` | Two historical archives explicitly retained by the owner. Do not duplicate or repack them. |

Protected personal/recovery/backup trees must not be opened, moved or deleted as housekeeping. Do not follow dependency/profile junctions during cleanup. The integration-preservation folder outside this checkout remains historical material and needs a separate decision before removal. The merged theme worktree checkout has been removed with owner approval; `theme-system-2026` and its commits remain in Git.

## Routine checks

Run `npm test`, `npm run localization:check`, `npm run build`, `node scripts/prepare-legal.cjs --check` and `node scripts/publication.mjs --check`. Build output is separate from accepted release artifacts. To package a new local development check, use `npm run build:win`; never point a build at an immutable RC folder. Commands do not install or publish. Ordinary tests do not replace physical Windows/installer checks.

`node scripts/inventory-workspace.cjs <receipt.json>` measures file metadata without opening file contents or following links. Protected directory names are excluded, so its totals are logical measured bytes, not a full personal-data inventory or allocated disk usage. It deliberately makes no deletions. Review its exclusions and any new directory names before treating an inventory as complete.

Source export remains an explicit allowlist. `node scripts/publication.mjs --output publication-local/<fresh-name>` requires a committed tree and refuses overwrite. The current checkout's export is a maintenance snapshot, not the matching source of an older binary; retain RC2's exact archive. No artifact is cleared for distribution by passing this command. See [asset review](ASSET_RIGHTS_AUDIT_20261018.md) and [build/source obligations](../SOURCE_BUILD.md).

Historical evidence paths in dated reports describe their original runs. Removed superseded build folders are not expected to remain runnable. Rebuild an appropriate commit in a new isolated checkout if a historical package is needed; do not reinterpret a current build as a historical binary. Keep source fixtures and regression scripts even after generated runs are removed.
