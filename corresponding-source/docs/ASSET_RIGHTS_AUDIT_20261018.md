# RC2 asset-rights audit — 18 October 2026

**Decision: keep the friend-testing package private and undistributed.** The approved F/R mark is demonstrably traced from a supplied raster whose creator, upstream references and distribution permission are unknown. The owner explicitly reported uncertainty and requested this hold. This is an unresolved provenance issue, not a finding of infringement. No asset was replaced, redesigned, uploaded or submitted to an image-search service.

## Scope and evidence

Reviewed the RC2 production ASAR, branding resources, renderer SVG/CSS/image references, Learn and Stats visuals, tray generation, sound synthesis, authoring scripts, available Git history, PNG metadata, license notices and the exact private-testing ZIP. Personal profiles, private recovery material and user-created drawings were not accessed. File history begins at existing checkpoints for several assets; a commit records possession, not authorship. Missing metadata cannot identify the creator or distinguish human work from generated artwork.

The ASAR contains 14 media entries: 12 F/R-derived files (including the compiled renderer icon), one support-cup SVG and one chime. Inline graphics are compiled into JavaScript/CSS and were inspected separately: 21 renderer source files contain SVG/image templates, plus CSS diagrams and the programmatic tray icon. Counts describe source templates, not the number of rendered states. Dynamic drawings and chart paths require source inspection as well as file-extension enumeration. Electron/Chromium/NSIS component resources are third-party software resources governed by their included upstream notices; this is not an independent rights investigation of every upstream operating-system/component glyph.

Receipts: [packaged media](verification/asset-rights-20261018/packaged-media.json), [inline graphics](verification/asset-rights-20261018/inline-graphics.json), [bounded library comparison](verification/asset-rights-20261018/library-comparison.json), [reference revisions](verification/asset-rights-20261018/upstream/manifest.json), [chime reproduction](verification/asset-rights-20261018/chime.json).

## Standard-library comparison and attribution

Downloaded official source archives of Lucide (`1ef60af944de207e0d5176905a0759ba12e6ee8d`), Feather (`3dc050d97405062eba78aa57115c0a15c63abdaa`) and Heroicons (`616b7a4dbbf3d011760af8066262cd5c6b3868f3`). Compared literal project SVG path command/number tokens against 5,297 SVG files, normalizing whitespace, commas and numeric formatting. No project artwork was uploaded. The comparison found only two generic candidates: a straight horizontal line in QuestionPreview and clock hands in DistractionVisual. These trivial shared shapes are not evidence that a library was copied. No distinctive complex path match was identified.

This test does not compare scaled/rotated paths, equivalent relative versus absolute commands, dynamic geometry, other libraries, all older revisions, whole images or visual similarity. A negative result cannot prove originality. File-first-appearance dates in the inventory are not creation dates for every subsequently edited path.

If a licensed replacement is later approved, preserve the exact pinned license/copyright notices: [Lucide's ISC and Feather-derived MIT notices](https://github.com/lucide-icons/lucide/blob/1ef60af944de207e0d5176905a0759ba12e6ee8d/LICENSE), [Feather MIT](https://github.com/feathericons/feather/blob/3dc050d97405062eba78aa57115c0a15c63abdaa/LICENSE), [Heroicons MIT](https://github.com/tailwindlabs/heroicons/blob/616b7a4dbbf3d011760af8066262cd5c6b3868f3/LICENSE). No such library was added by this review. Existing dependency notices remain required and are included in the unchanged package. Those notices do not clear unverified project assets.

## Generation, tracing and the project's license

GPL-3.0-only is the owner's final license choice for rights the project can grant; it does not supply missing permission from an upstream artist or reference owner. Generated or traced outputs need their input history and applicable permissions reviewed. Human authorship and rights in AI-assisted output are also jurisdiction-dependent; the [US Copyright Office's guidance](https://www.copyright.gov/newsnet/2025/1060.html) concerns US copyrightability, not worldwide permission or proof of noninfringement. [Microsoft's font FAQ](https://learn.microsoft.com/en-us/typography/fonts/font-faq) distinguishes using fonts in graphics from shipping font files. This report is an evidence inventory, not legal or trademark certification.

Corrected ASSETS.md and branding/README.md where "original" previously overstated available evidence, particularly the support banner that actually includes the traced logo. The archived RC2 source and binary were not silently changed to update those historical descriptions.

## What resolves the hold

1. Locate the original F/R design/generation conversation, designer delivery or source URL. Establish creator, applicable license/permission, supplied image references and permission to use those inputs. Metadata and a visual resemblance search alone cannot establish permission. No relevant creator/source record has been found in the available project history.
2. Obtain the UI/illustration author's account of external references, copied paths and generation tools, including the support cup. Record any identified licenses and required notices. The available source supports a code-authored classification, not a categorical original/AI label.
3. If the F/R provenance cannot be verified, the safe fallback is a separately approved, independently documented logo commissioned or authored from a written brief without the uncertain reference. For unresolved icons, a reviewed, pinned MIT/ISC library is a practical alternative; for explanatory scenes, documented independent drawings are possible. These are recommendations only: no redesign or asset replacement is authorized or implemented.
4. Re-review matching source/notices and package contents after any approved change. A replacement would require a newly identified candidate; do not overwrite the verified RC2. The full Electron/Chromium/Node transitive source tree is not mirrored in this package; its existing source-access instructions and availability still need release review. Package integrity does not certify Corresponding Source sufficiency.
